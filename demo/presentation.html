CloudPulse Platform

End-to-End DevOps & DevSecOps Capstone Project

Session 21: Production Delivery Pipeline & Infrastructure Automation

  • Domain: Multi-Cloud Infrastructure & Asset Inventory Management
  • Stack: React 18, FastAPI, PostgreSQL, Docker, AWS EKS, Terraform, Helm
  • Pipeline: GitHub Actions, Pytest, DevSecOps (Trivy, Gitleaks, Bandit)
  • Observability & GitOps: Prometheus, Grafana, ArgoCD
  • Repository: github.com/soleilbrulant/cloudpulse-devops-capstone

Problem Statement & Project Objectives

  • Challenge: Cloud sprawl, visibility gaps across AWS/GCP/Azure, untracked orphan assets, and configuration drift.
  • Solution: CloudPulse delivers a unified inventory plane for asset tracking, health monitoring, and spend attribution.
  • DevOps Mandate: Automate the entire delivery lifecycle from commit to AWS production using modern best practices.

System Architecture Flow

  • Code Commit: Feature branch merged to main on GitHub.
  • CI / DevSecOps: Pytest (12 tests) → Vite build → Bandit SAST → Gitleaks → Aqua Trivy scanner.
  • Container Registry: Hardened images pushed to GitHub Container Registry (GHCR).
  • Cloud Infrastructure: AWS VPC, Subnets, Internet Gateway, and Amazon EKS managed by Terraform.
  • Kubernetes Orchestration: Deployments, Services, ConfigMaps, Secrets, Ingress, and HPA packaged in Helm.
  • GitOps: ArgoCD automatically reconciles cluster state with the Git repository.
  • Monitoring: Prometheus scrapes /metrics via ServiceMonitor; Grafana provides real-time dashboards.

Application & Database Architecture

  • FastAPI Microservice: High-throughput Python 3.12 async backend with Pydantic v2 schemas and SQLAlchemy 2.0 ORM.
  • PostgreSQL 16: Deployed as a Kubernetes StatefulSet with 5Gi PersistentVolumeClaim.
  • Alembic Migrations: Schema migrations execute automatically before application startup.
  • React 18 Dashboard: Modular SPA with real-time spend aggregation and cloud provider filtering.

Containerization & Docker Security

  • Multi-Stage Builds: Strips build tools, compilers, and dev dependencies, minimizing attack surfaces.
  • Non-Root Execution: Backend runs as UID 10001 (appuser); Frontend runs as UID 101 (nginx).
  • Image Footprint: Minimal alpine/slim images (<180MB).
  • Local Development: One-command startup via docker compose up -d.

Infrastructure as Code (Terraform)

  • AWS VPC: Dedicated 10.0.0.0/16 network with multi-AZ public subnets (ap-south-1a & ap-south-1b).
  • Amazon EKS: Managed control plane with IAM Role integration.
  • Managed Node Group: 2x t3.medium instances with autoscaling up to 4 nodes.
  • Idempotency: Declarative state management with complete clean teardown support.

Kubernetes & Helm Deployment

  • Workload Components: Deployments, ClusterIP Services, ConfigMaps, Secrets, Ingress, and StatefulSet.
  • Resilience & Health: Liveness (/health) and Readiness (/ready) probes.
  • Autoscaling: Horizontal Pod Autoscaler (HPA) targeting 70% CPU (2 to 6 replicas).
  • Helm Packaging: Parameterized values for dev and prod environments with full lint validation.

CI/CD & DevSecOps Pipeline

  • Testing Gate: Automated Pytest suite executes 12 unit/integration tests with SQLite in-memory DB.
  • SAST: Bandit scans Python codebase for security vulnerabilities.
  • Secret Scanning: Gitleaks detects committed credentials or tokens.
  • Vulnerability Scanner: Aqua Trivy scans container images; fails build on CRITICAL/HIGH vulnerabilities.
  • Automated Release: GHCR publishing with Git SHA tagging.

Monitoring & GitOps

  • Prometheus Operator: Automated scraping via ServiceMonitor every 15 seconds.
  • Grafana Golden Signals: Real-time panels for Request Rate, Latency (P50/P95/P99), Error Rate (5xx), and Pod Replicas.
  • ArgoCD Continuous Reconciliation: Git repository as the single source of truth; automatic drift correction and rollbacks.

Troubleshooting & Production RCA

  • Incident 1: ImagePullBackOff:
    Root Cause: Non-existent image tag specified in deployment.
    Remediation: Corrected image tag to verified release and validated pod readiness.
  • Incident 2: 502 Bad Gateway / Endpoints <none>:
    Root Cause: Service selector mismatch with Pod template labels, and incorrect targetPort (8080 vs 8000).
    Remediation: Aligned selector labels and targetPort; verified healthy endpoint population.
